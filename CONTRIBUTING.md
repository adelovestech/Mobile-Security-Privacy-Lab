# Contributing

Contributions are welcome when they improve clarity, correctness, and reproducibility.

1. Open an issue describing the question or correction.
2. Cite official documentation for technical claims; specify review date.
3. Keep consumer advice distinct from measured device observations.
4. Use synthetic accounts and test data; redact all screenshots.
5. Never submit exploit payloads, personal secrets, employer data, or unauthorized testing results.
6. Open a pull request with a short summary, testing context, and limitations.

Content should be accessible to nontechnical readers and defensible to security practitioners. Prefer neutral comparisons over declaring a platform categorically safer.
